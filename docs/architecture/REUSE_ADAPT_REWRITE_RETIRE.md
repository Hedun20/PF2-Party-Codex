# Reuse / adapt / rewrite / retire matrix

- **Baseline:** `origin/main@372f88fc070313c351ddce830647c355db8a39b7`
- **Decision point:** HED-20 repository audit
- **Rule:** “reuse” means preserve behavior through tests and a typed boundary; it does not mean copy JavaScript unchanged into the target.

## Decision vocabulary

| Decision | Meaning |
|---|---|
| **Reuse** | Current domain behavior and ownership are sound enough to preserve behind a typed port. Refactoring is allowed. |
| **Adapt** | Preserve the capability, but change its interface, ownership, storage, or lifecycle before using it in the target. |
| **Rewrite** | Rebuild the boundary because its present architecture conflicts with Next App Router, strict TypeScript, security, or maintainability. Preserve only explicitly characterized behavior. |
| **Retire** | Do not port into the archive-first target. Keep temporarily only as rollback/compatibility until its removal gate is met. |
| **Defer** | Keep the current module outside the first slice; decide later after core archive contracts stabilize. |

Proposed target ownership names are architectural boundaries, not authorization to scaffold them during HED-20:

- `packages/contracts`: strict TypeScript DTOs, runtime schemas, IDs, errors, and API compatibility fixtures.
- `packages/core`: system-neutral domain entities and policies.
- `packages/application`: use cases and ports; no Express, Next, Mongo, or browser imports.
- `packages/mongo`: repositories, query builders, migrations, and serialization adapters.
- `packages/integrations`: Markdown, Foundry, Pathbuilder, email, object-store, and future AI/event adapters.
- `apps/web-next`: future Next.js App Router application after the prerequisite gates pass.
- `apps/worker`: future separately deployable outbox/import/event worker when required.

## Cross-cutting migration invariants

These invariants apply to every row in the matrix:

1. Every campaign operation receives an authenticated principal and an exact, server-verified campaign context.
2. Player responses are constructed from allowlisted fields; GM-only data is not fetched and then hidden in the browser.
3. MongoDB owns domain state. Markdown and Foundry files are compatibility/import/export artifacts.
4. A mutation is idempotent where retries are plausible and emits an auditable fact without logging secrets.
5. Strict TypeScript and runtime input validation meet at the transport boundary; TypeScript alone does not validate network or database data.
6. PF2e-specific code depends on the system-neutral core, never the reverse.
7. Each slice has a documented rollback path to the Express/Vite implementation until production evidence supports retirement.

## Explicit non-decisions

HED-20 does not select a billing vendor, object-store vendor, CSS framework, schema library, auth library, hosting provider, AI model, queue vendor, or Foundry module protocol. Those choices should be made only when the corresponding port and acceptance criteria are approved. The matrix defines required behavior and ownership so those vendor decisions remain replaceable.
